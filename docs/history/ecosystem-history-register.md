## 1. Purpose

This register preserves the known history, current activities, and planned initiatives of the Hip Hop Peoples / MAEG / Krafty Academy / Hip Hop Healing Institute ecosystem in a controlled repository file.

The purpose is to create a documented evidence trail that institutions, partners, funders, reviewers, underwriters, workforce boards, and internal operators can use to understand the evolution of the ecosystem without relying on social media posts, informal memory, or scattered documents.

This file is not a marketing page, investment offer, clinical record, participant file, payroll record, or legal claim. It is a structured historical index.

---

## 2. Evidence Standard

Each activity should eventually be supported by one or more of the following:

- Website page
- Notion-controlled document
- Grant file
- Fiscal sponsor record
- Contract or MOU
- Program flyer
- Event record
- Stripe or registration record
- Google Form intake record
- Production file
- GitHub commit or architecture document
- Partner correspondence
- Photo/video archive
- Public-facing announcement

Where formal documentation is still pending, entries should be marked as **Pending Verification**.

Financial figures, billing targets, grant figures, production budgets, revenue targets, and compliance statuses in this register are institutional-memory entries only until tied to source documents such as CIOS-REV-001, audited financials, fiscal sponsor records, lender memoranda, payroll reports, bank records, NCWorks/ETPL files, or production ledgers.

---

## 3. Control Language

The ecosystem uses the following institutional framing:

> Creating a documented evidence trail that institutions can review, underwrite, verify, and respond to through their existing compliance processes.

This register should preserve historical continuity while avoiding overstatement. Activities should be classified by status, lane, and supporting evidence.

---

## 4. Activity Status Definitions

| Status | Meaning | Minimum Evidence Required |
|---|---|---|
| Active | Activity is currently operating, being tracked, used, or institutionally governed. | At least one active source record, dashboard, SOP, website page, registration/payment record, partner record, or operating file. |
| Planning | Activity is designed, proposed, or being prepared but is not yet fully operating. | Planning document, blueprint, draft SOP, site plan, budget, form, internal memo, or approved concept note. |
| Pending Verification | Activity, metric, compliance status, or claim has been reported but needs source documentation before external use. | Primary source evidence must be attached or linked before the item is used in grant, lender, underwriting, public, or compliance packets. |
| Archived | Activity is no longer active but remains part of ecosystem history. | Prior records, flyers, photos, correspondence, or summary memo. |

### 4.1 Status Upgrade Rule

No entry should move from **Pending Verification** to **Active** based on memory, conversation, or informal claim alone. The upgrade requires source evidence tied to the correct file lane.

Examples:

- Financial figure → CIOS-REV-001, ledger, bank record, fiscal sponsor record, invoice, receipt, payroll export, or accounting file.
- Workforce placement → MAEG-WF-SOP-001 status evidence, participant dashboard, assignment record, supervisor confirmation, timesheet, or payroll proof.
- Clinical or Medicaid-related claim → NCTracks enrollment, licensed-provider documentation, service definition, payer enrollment, supervision records, or clinical partner record.
- Youth program claim → parent/guardian intake, youth safety file, licensing/registration record if applicable, insurance/risk controls.
- Production spend → production ledger, payroll export, vendor invoice, proof of payment, call sheet, qualified spend ledger, or CPA/AUP file.
